# Пульт оператора

Как консоль в `web/` доносит состояние смены. Контракт HTTP — `web/openapi.yaml`. Глобус — картинка Kepler, не физика заряда и не назначение заданий.

После значительного изменения UI этот файл дополняется.

## Сетка

Полноэкранная тёмная консоль, три колонки:

| Зона | Что видит оператор |
|---|---|
| Верх | id сценария, длительность смены, цель (Приоритеты / Деньги), Запустить / Пауза, Шаг вперёд, Ещё |
| Слева | список КА: заряд, температура, возраст калибровки, действие |
| Центр | 3D-глобус и таймлайн |
| Справа | инспектор: спутник / задания / события |
| Низ | сводка смены; клик раскрывает ещё три числа |

Шаг смены — 5 минут. Часы на таймлайне: `шаг × 5` мин (`00:00` на шаге 0). Курсор смены — `state.step`; наведение на таймлайн даёт `previewStep` и не двигает смену.

## Цвет

Один словарь на дерево, глобус и таймлайн. Коды в `web/static/css/console.css` (`:root`).

### Действие КА (сигнал политики)

| Цвет | Код | Где | Смысл |
|---|---|---|---|
| Белый `#e8ebef` | `--sig-idle` (`--text`) | точка на глобусе, статус в дереве | ожидание — тот же цвет, что у заданий в статусе «ожидание» |
| Зелёный `#3ddc6a` | `--sig-job` | то же | выполнение задания |
| Фиолетовый `#8b7fd4` | `--sig-cal` (`--accent`) | то же | калибровка — тот же цвет, что у заданий «в работе» |
| Серый `#8a8a8a` | `--unavailable` | дерево | КА недоступен |
| Тусклый (opacity 0.38) | `.is-faded` | строка КА / задания | сейчас нельзя взять или назначить (`can_execute` ложь). Просроченное, которое **ни разу** не было в доступе, тоже тусклое |

Легенда на глобусе: «зелёный — задание, белый — ожидание, фиолетовый — калибровка · тусклые — сейчас нельзя взять». Тусклая точка — тот же цвет действия, смешанный с `#3a404c`. Ожидание при `take=1` остаётся ярким: политика выбрала ждать.

### Здоровье (заряд и температура)

| Цвет | Код | Порог | Где |
|---|---|---|---|
| Зелёный `#5cad5c` | `--ok` | SOC ≥ резерв | полоска заряда; точка, если нет угрозы |
| Оранжевый `#f0a040` | `--warn` | резерв > SOC ≥ critical | полоска заряда и точка — предупреждение о заряде |
| Красный `#e05555` | `--danger` | SOC < critical **или** \|T\| ≥ 130 °C | точка; полоска заряда только при разряде; число температуры при перегреве; просроченные / невыполнимые задания |

Пороги `reserve_soc_pct` / `critical_soc_pct` — из JSON смены (`model`). Предел температуры на пульте — ±130 °C, как пунктир на графике. Точка красная, если разряжен **или** перегрет; оранжевая — только предупреждение по заряду. Полоска SOC не красится в красный из‑за температуры.

### Прочее

| Цвет | Зачем |
|---|---|
| Сирень `#8b7fd4` (`--accent`) | выбранный КА, кнопка «Запустить», точка «сейчас» на графике, задание в работе, калибровка КА |
| Лиловая кривая `#c4bdf5` | качество политики `q` на таймлайне |
| Белая вертикаль | текущий шаг смены на таймлайне |
| Белый шар с сиреневой обводкой | шаг, на который навелись |
| Пунктир `--warn` на графике заряда | линия резерва |
| Пунктир `--danger` на графиках | critical SOC / ±130 °C |
| Зелёный `--ok` / оранжевый `--warn` | метки таймлайна ok / warn |

Статусы заданий в инспекторе: ожидание — белый текст, активное — accent, выполнено — ok, просрочено и невыполнимо — danger.

## Загрузка смены

Старт — экран сброса JSON (`cosmo-B-ops-1.0`). Превью: имя файла, размер, число КА, шаги, задания, потенциал выручки. «Запустить смену» шлёт JSON на `/api/scenario`, затем параллельно орбиты и прогон политики. Пока качается — оверлей «Пересчёт политики» (тот же спиннер, что при событиях).

Демо-кнопка читает `web/src/mocks/P01_intro.json` (копия `task/data/P01_intro.json`). Можно сбросить любой JSON `cosmo-B-ops-1.0` из `task/data/`.

## Верхняя полоса

- **Орби.tar** — слово-логотип слева, затем **id сценария** и «N шагов (H ч)».
- **Приоритеты / Деньги** — цель награды OpsEnv и чекпоинт с шага k (`priority` → `ckpt_68120`, `revenue` → `ckpt_35714`). Смена спрашивает подтверждение. Модалка считает развилку на **+10 шагов**: общий префикс живого прогона, с k — другая сеть (`POST /api/dispatch/whatif`). Шесть строк как в нижней сводке: остаться на k+10 → сменить на k+10, зелёный ↗ / красный ↘. Пока кадра нет — «считаем…». «Сменить» переигрывает хвост новой сетью (`POST /api/dispatch/resume`); «Отмена» не трогает прогон. Считать можно до прихода кадра k — тогда «Сменить» неактивна.
- **Запустить** — автопрогон по 450 мс на шаг; **Пауза** останавливает.
- **Шаг вперёд** — один тик. Если на текущем шаге есть черновик события, оно фиксируется и хвост смены пересчитывается сетью (см. События).
- **Ещё**: переход к шагу N, загрузка сценария заново, выгрузка журнала `cosmo-B-ops-result-1.0` (`/api/result`, лимит 120 Мб).

Ошибки (нет журнала, слишком большой файл, сбой пересчёта) — модалка «Сообщение».

## Дерево спутников

Строка: точка здоровья · id · полоска+процент SOC · температура °C · шаги после калибровки · действие. Действие: выполнение зелёным, ожидание белым, калибровка фиолетовым. Полоска заряда оранжевая при предупреждении, красная при разряде. Температура красная при \|T\| ≥ 130 °C. Точка красная при разряде или перегреве.

Сортировка: сначала выполняющие задание, затем калибровка, ожидание, недоступные; внутри — по id. КА, которым **сейчас нечего взять** (`take=0` в кадре), прозрачные и всегда в конце списка. Подсказка строки: «Сейчас нельзя назначить задание».

Ожидание при `take=1` не тускнеет — сеть могла взять работу и не взяла.

Фильтры: Все / Проблемные (не ok) / Критические. Поиск по id, job_id и подписи действия.

Клик по строке выбирает КА: подсветка в дереве, карточка справа, точка на глобусе в HUD.

Данные кадра — физика `sim/ops` через поток `/api/dispatch` (energy, temp, calibration_age, action после repair).

## 3D-глобус

Kepler-картинка (`/api/tracks`, запасной срез `/api/orbits`). Не `solar_w` и не окна связи из JSON.

- Земля с текстурой, звёзды, линии орбит (полупрозрачный белый), точки КА.
- Солнце — направленный свет из ECEF того же Kepler-мира.
- Цвет точки = действие на **просматриваемом** шаге (лента `action_tape`, иначе текущее действие): зелёный job, белый idle, фиолетовый calibrate. Если КА idle и `assignable=false`, точка тускнеет.
- HUD: шаг, выбранный id, легенда «зелёный — задание, белый — ожидание, фиолетовый — калибровка».
- Перетаскивание вращает камеру; короткий клик по точке выбирает КА.
- Наведение на таймлайн двигает точки и солнце на `previewStep`, не меняя `state.step`.

Назначения заданий глобус не делает.

## Таймлайн

Под глобусом. Кривая — **качество политики `q` из кадра**, не клиентская эвристика поверх метрик.

`q = 0.5 · sigmoid(value / remaining_job_usd) + 0.5 · heuristic`, где `value` — critic той же сети (`HARMONY_MODEL`, сейчас `ckpt_68120`), heuristic — SOC ≥ резерв, P3 ещё в срок, доля не idle, нет новых просрочек. Заливка кривой — до текущего шага смены; линия на всю длину, по мере прихода кадров.

Шапка: число шагов · «Меток событий N» · **«Преимущество текущей политики: N%»** (`round(q × 100)` на текущем шаге, иначе прочерк). Справа — часы просматриваемого шага.

Метки — первый переход порога по уже пришедшим кадрам, каталог `web/src/timeline-marks.json`:

| id | Тон | Когда |
|---|---|---|
| `revenue_half` | ok (зелёный) | выручка ≥ 50% потенциала исходного списка |
| `overdue` | warn (оранжевый) | просрочек ≥ 1 |
| `soc_reserve` | warn | хотя бы один КА ниже резерва |
| `seed_done` | ok | закрыто ≥ 80% исходных заданий |

Клик по метке открывает карточку в вкладке «События» и ставит `previewStep`. Клик по дорожке — только наведение. Белая палка — текущий шаг; шар — шаг наведения.

Подпись: «Текущий шаг N · Вы навелись на M шаг».

## Инспектор: спутник

Параметры из JSON (ёмкость, мощности) + живое состояние кадра (заряд %, температура, возраст калибровки, действие).

Два графика на всю длину смены, ряд до последнего пришедшего кадра:

1. **Заряд, %** — 0…100, пунктир резерва и critical, вертикаль «сейчас», подпись «текущее · резерв · критическое».
2. **Температура, °C** — −150…150, пунктир ±130 °C.

Ниже: лента действий по шагам; отклонённые команды (после repair в норме пусто); текстовый статус («свободен», «выполняет задачу», «нет задания, которое можно взять»). Поле «Можно взять задание»: да / нет по `Environment.can_execute` на текущем шаге (не маска top-K).

## Инспектор: задания

Список: id, приоритет, статус (ожидание / занят / выполнено / просрочено / невыполнимо). Фильтры: все, выполненные, просроченные, высший приоритет. Поиск.

Порядок (все фильтры): активные → ожидание, которое **можно** назначить → выполненные → просроченные, которые **были** в доступе → просроченные, которые **ни разу** не открывались → невыполнимые → ожидание, которое сейчас нельзя назначить (самый хвост). Просроченные без доступа тусклые, но остаются в группе просроченных, не уезжают в конец всего списка.

Тусклые строки (opacity 0.38): ожидание/невыполнимо, которое сейчас нельзя назначить; просроченное, которое ни разу не было в `open`.

Карточка: тип (ретрансляция / передача на Землю), окно шагов, исполнители, выручка, прогресс `сделано/нужно · кто вёл`, статус, **«Была в доступе»** — «на шаге N» (первый кадр с `open`) или «Не была в доступе». Блок «Анализ текущего состояния» — человеческий x-ray.

Источник доступа: кадры `/api/dispatch`, поля `open` (индексы заданий) и `take` (0/1 по КА). `first_open_step` считает клиент по уже пришедшим кадрам 0…view.

Новые задания с `add_jobs` появляются в списке после пересчёта хвоста (meta потока).

## Инспектор: события

Черновик только на текущем шаге смены (`eventComposeAt === step`). «+»: новое срочное задание, спутник недоступен, отмена сеанса; либо JSON `cosmo-B-events-1.0`. Пока не сделали «Шаг вперёд» — статус «черновик», можно править и отменить.

Шаг вперёд фиксирует событие и вызывает `/api/dispatch/resume`: тики до k — старые команды, с k — сэмпл PPO, `apply_event` до действия. На экране оверлей «Пересчёт политики», пока не готов кадр нового шага. Кривая слева не откатывается; хвост `q` и все поля смены (КА, задания, метрики) берутся из нового потока.

Клик по метке таймлайна показывает её карточку здесь (зелёная или оранжевая рамка), даже если операторских сообщений ещё нет.

## Нижняя сводка

Строка по центру, дельта слева от каждого показателя (зелёный ↗ лучше, красный ↘ хуже, серый `—` / `0%` без сдвига).

| Показатель | Число | Откуда дельта |
|---|---|---|
| Выполнено P3 в срок `done/due` | накопитель текущего прогона | **вторая политика** на том же шаге (`jobs_completed`) |
| Просрочено | то же | **+10 шагов** текущей политики |
| Выручка $ | то же | **вторая политика** на том же шаге |
| Критическое состояние заряда (brownout) | то же | **+10 шагов** текущей политики |
| Заряд ниже резерва | то же | **+10 шагов** текущей политики |
| Отклонённых команд | то же | без дельты (после repair 0) |

Горизонт — 10 шагов или конец смены, что ближе. Процент: `|b − a| / max(|a|, ε)`. Для просрочки и заряда рост числа — плохо (красная ↘). Для выручки и выполненных сравнение с `HARMONY_ALT_MODEL` (`ckpt_35714`, выручка): больше нас, чем у второй сети — зелёная ↗.

Вторая политика стартует при импорте JSON (`GET /api/dispatch/alt`). Пересчитывается только вместе с `POST /api/dispatch/resume` после события или после подтверждённой смены цели. Шаг вперёд без сообщения хвост второй политики не трогает.

Модалка смены цели сравнивает не две траектории с шага 0, а **развилку с текущего k**: «остаться» — кадр живого прогона на min(k+10, конец); «сменить» — `POST /api/dispatch/whatif`. Кеш по шагу+цели+событиям; prefetch текущего (и следующего при автопрогоне) шага. После resume кеш сбрасывается.

Клик по строке раскрывает: заданий всего, выполнено, потенциал $.

## Оверлей загрузки

Полный экран, спиннер, подпись «Пересчёт политики». Блокирует клики. Включается при загрузке JSON смены и при пересчёте после событий.

## Заглушки

- **Сравнение вариантов** (`CompareView`) — полноэкранная заглушка «Приоритеты vs Деньги».
- Сравнение двух политик на графиках прогона (`agent.baseline`) отдельно. На пульте нижняя сводка сравнивает выручку и выполненные задания с `HARMONY_ALT_MODEL` на том же шаге (независимый прогон с 0). Модалка смены цели — развилка с k на +10 шагов.
